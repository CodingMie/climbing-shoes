# 06 — 聚合展示

**What to build:** 鞋款详情页聚合展示该鞋的测评数据：七个维度的平均分与测评数、尺码偏移分布（按偏移值分桶的占比，如「-1.0：45%」，文案形如「60% 用户建议比日常小 1 码」）、合身度反馈分布（六个部位各选项的占比）。聚合随测评数据实时变化，帮助访客快速判断尺码与合身风险。

**Blocked by:** 05 — 测评：创建/编辑/删除

**Status:** done

- [x] 尺码偏移分布按 0.5 步长分桶展示占比
- [x] 合身度反馈分布展示六个部位各选项占比
- [x] 无测评的鞋款展示空状态而非错误

## Comments

- 2026-08-04 开工前讨论（ticket 07 推进时）：用户提出「评分严重依赖脚型，只做简单数据聚合无效」——合脚类维度（舒适/包裹/合身度）的均分会把不同脚型的体验混在一起，可能误导。动手前应先定聚合方向：全局聚合 + 样本量标注、按脚型分组（数据稀疏时降级）、还是按脚型筛选测评列表优先。spec 已把「同脚型聚合/脚型匹配」划为二期（L20、L170-172），但本 ticket 的简单聚合是否照做、以什么形态呈现，需先与用户对齐。
- 2026-08-04 落地备注：与用户对齐后按「脚型筛选聚合」方向实现（即 spec 二期方向的前置落地）。聚合逻辑在 `src/lib/reviews.ts` 的 `getShoeReviewStats(shoeId, footFilters)`：一次查出该鞋全部测评（left join foot_profile），按脚型条件（脚型/脚宽窄/脚后跟，沿用鞋库的 `footShape`/`footWidth`/`footHeel` 参数，可任意叠加）在 JS 侧过滤后计算七维度均分（保留 1 位小数）、尺码偏移分桶占比（众数桶生成「N% 用户选择比日常小 X 码」标题）、六部位合身度占比（只展示出现过的选项）。无匹配返回 null，页面区分「无测评」与「无匹配脚型」两种空状态。测评者无脚型档案时不参与脚型筛选匹配（无筛选时仍计入）。鞋详情页新增「测评数据」区块（GET 表单筛选，与鞋库同参数）；鞋库卡片链接在脚型筛选激活时携带参数进入详情页。共享下拉组件抽到 `src/components/shoes/filter-select.tsx`；顺带按 CONTEXT.md 修正脚型筛选标签术语（脚宽窄/脚后跟）。E2E 在 `e2e/aggregates.spec.ts`（serial 模式 + 幂等 DB 种子，6 条：全局聚合数值、埃及脚筛选、叠加筛选、无匹配空状态、无测评空状态、鞋库→详情页参数传递）。测评列表本身不随脚型筛选过滤（卡片已带作者脚型摘要）。
